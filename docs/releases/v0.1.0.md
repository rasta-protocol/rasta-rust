# RaSTA-Rust v0.1.0

Released 2026-11-01.

## Summary

The first release of an independent, experimental Rust implementation of the
Rail Safe Transport Application (RaSTA) protocol: a deterministic,
allocation-free protocol core for the Safety and Retransmission Layer and the
Redundancy Layer, with UDP and simulation adapters. It is not certified, and
its behaviour is based on observations of public MIT-licensed
implementations, not on the normative specification.

## Highlights

- `StackEngine` composes both layers without I/O: the host feeds it
  application commands, received datagrams, and the current time, and executes
  the actions it returns.
- Safety and Retransmission Layer: connection establishment, heartbeats,
  adaptive timing, flow control, retransmission, packetization
  (`N_maxPacket`), and the MD4 safety code with configurable initial values.
- Redundancy Layer: one or two transport paths, duplicate suppression, a
  bounded defer queue with `T_seq`, five check-code profiles, and a receive
  queue that holds received messages while the application is slow.
- Diagnostics as in the reference implementations: SR error counters and
  `T_rtd`/`T_alive` distributions, and per-path RL diagnostics.
- A UDP adapter, a deterministic network simulator, and an interactive example
  node (`examples/udp_peer.rs`) with a [guide](../trying-it-out.md).
- Interoperates with EULYNX Live librasta.

## Breaking changes and migration

None: this is the first release.

## Compatibility

- Minimum supported Rust version: 1.83. CI builds and tests on Linux,
  Windows, and macOS with Rust 1.83 and with the pinned toolchain.
- No third-party dependencies.
- Cargo features: `std` (default) adds the UDP adapter and the simulator.
  Without default features the protocol core is `no_std` and allocates no
  memory.
- Memory per connection on x86-64: about 90 KiB for `StackEngine`. The
  allocation-free operations also need a `StackWorkspace` (about 122 KiB) and
  `StackActions` (about 47 KiB), which several connections can share in turn.
  With that storage placed outside it, CI checks the operations on a task
  stack of 64 KiB (128 KiB on Windows).
- Wire profile: the protocol version is configuration; `0303` is used in tests
  and interoperability runs. Safety code: none, lower MD4, or full MD4. Check
  codes: none, CRC-32 with polynomial `0xEE5B42FD`, CRC-32C, CRC-16/KERMIT, or
  CRC-16/ARC. One `StackEngine` carries one connection.
- Verified interoperability: EULYNX Live librasta `be81878` (2026-11-01, both
  roles, without a safety code and check code, and with lower MD4 and
  CRC-32C). The SBB stack `81f2a8f` was verified on 2026-10-10 against an
  earlier revision of this code; that run has not been repeated for this
  release. See [differential testing](../differential-testing.md).

## Known limitations

- Not certified, and no conformance is claimed. There is no normative
  baseline yet; see the [open questions](../open-questions.md).
- RaSTA detects transmission errors but does not authenticate messages. Use a
  separate security layer on networks that are not physically protected; see
  the [threat model](../../SECURITY.md#threat-model).
- Applications must keep at least three send-buffer entries free. As in the
  SBB reference, the stack processes no received message while fewer are
  free, so the connection times out.
- The configuration ranges that the SBB reference validates are not enforced.
- The reason in a received disconnection request is not reported, and sent
  disconnection requests carry detailed reason zero.
- The convenience operations (`step_connection`, `receive_datagram`, `poll`)
  copy the engine on the stack. Use the `*_into` operations with persistent
  storage on small stacks.
- No coverage-guided fuzzing yet; parsers are tested with deterministic
  pseudo-random input.
